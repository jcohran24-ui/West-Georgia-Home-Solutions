CRITICAL CONTRACTOR FORM FIX

CAUSE
The previous contractor form generated an invalid inline onsubmit attribute around
"Founding Partner". The browser therefore performed a normal GET submission.
That caused contractor information to appear in the URL and prevented the
application from reaching /api/partners.

FIX
- Removed the inline onsubmit handler.
- Added a proper JavaScript submit event listener.
- Added method="post" action="/api/partners" as a safe fallback.
- Contractor details no longer belong in the URL.
- Existing success popup and Application Reference ID remain.

UPLOAD TO GITHUB
Replace only:
public/index.html

Then let Render redeploy.

TEST
1. Open the site in a fresh/private browser tab after deployment.
2. Open For Contractors.
3. Submit a new test application.
4. The URL should NOT change to include business/name/phone/email.
5. You should see the Application Submitted popup with a Reference ID.
6. Open /admin and click Refresh.
7. The contractor application should appear.

PRIVACY NOTE
Because earlier test submissions placed data in the URL, clear that test URL from
browser history if it contained real personal information.
